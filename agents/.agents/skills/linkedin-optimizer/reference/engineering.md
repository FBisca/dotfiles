# Engineering profiles

Extra guidance when the person is a software engineer (any discipline: frontend, backend, full stack, mobile, data, ML, platform, SRE, security).

## Titles
- Use titles recruiters search: "Senior Software Engineer", "Full Stack Engineer", "Backend Engineer", "Staff Engineer", "Engineering Manager", "Android Engineer", "ML Engineer". Internal levels ("SDE II", "L5", "Engineer III") → market equivalent in the headline; keep the real title in Experience if they prefer, or "Senior Software Engineer (L5)".
- Mixed history (e.g. mobile → full stack): headline leads with the target, earlier specialty as a differentiator ("… | 10+ yrs Android").

## Headline examples (fictional)
- `Senior Backend Engineer | Go · Kafka · PostgreSQL | Payments & Fintech | Ex-<Notable Co>`
- `Full Stack Engineer | TypeScript · React/Next.js · Node · Python | AI Agents & LLM Workflows | B2B SaaS`
- `Staff Platform Engineer | Kubernetes · Terraform · AWS | Developer Productivity at scale`

## Keywords
- Name languages, frameworks, cloud, data stores explicitly; recruiters filter on them. Write both forms once where common: "React.js (React)", "Large Language Models (LLMs)".
- AI-era keywords if true: AI agents, LLM workflows, RAG, evals, agentic development, MCP.
- Don't list every tool ever touched; 20–40 skills, tagged per role.

## Bullets
- Pattern: **verb + what + for whom + outcome**. "Built the quote-to-purchase funnel across the mobile and web apps."
- Product-generic wording when details are confidential: "Built internal tools that let operations scale without growing headcount at the same pace."
- Metrics only if true and allowed: latency, uptime, conversion, revenue impact, users, team size, cost.
- Mention scope/leadership: owned end to end, led N engineers, mentored, set architecture.

## Mining code for content (with permission)
- Read READMEs, package manifests (`package.json`, `pubspec.yaml`, `build.gradle`, `pyproject.toml`), infra configs, CI files to extract the real stack and architecture (monorepo, pipelines, apps).
- Turn findings into generic, public-safe bullets; never quote internal names, clients, endpoints, secrets or numbers (rule 4).
- Side projects with public URLs → Projects section with stack and link.

## Projects
- Name · one-line what + who it's for · stack · link · dates. Solo vs co-built stated honestly.
- Freelance/side business: check employer conflict first (rule 3).

## Open to Work titles
LinkedIn's list may lack niche titles ("Founding Engineer"); pick the closest (Senior/Lead/Staff Software Engineer, Full Stack Engineer) and tell the user.
